# Interface versions

The plugin interface has a major and a minor version, `MAJOR.MINOR`. A plugin's manifest says which it was built for (`"interface": "1.1"`), and the SDK it was built with knows that version.

| Version | Since | Adds |
| --- | --- | --- |
| 1.0 | OxiGuitar 0.2 | Formats (read and write), services, instruments (declared), footer messages, settings |
| 1.1 | OxiGuitar 0.2 | Tabs (widgets and a canvas, version 1 of the display list), pushed events, the open score |
| 1.2 | OxiGuitar 0.5 | The score version 2, which grows by extensions; the editor's selection (`Event::Selection2`); tools in the Tools menu and changes to the score, each one step the user can undo ([Tools and changes](tools.md)) |
| 1.3 | OxiGuitar 0.9 | A settings window ([Settings](settings.md)); sections of the track dialog ([Track sections](track-sections.md)); footer messages with a link; the plugin's folders; instruments and effects on the audio thread ([Instruments](instruments.md)); audio devices; the `cpu` condition ([Conditions](manifest.md#conditions)) |
| 1.4 | OxiGuitar 0.11 | A link among a tab's widgets (`Widget::Link`, [Tabs](tabs.md)), which the core opens in the browser; exporters in File → Export, audio ones getting the score's sound ([Exporters](exporters.md)); plugins that need other plugins (`needs`) and plugins that take over another's id (`replaces`, [The manifest](manifest.md)); advice, a dialog the user can silence (`Host::advise`, [Advice](advice.md)) |
| 1.5 | OxiGuitar 0.14 (frozen) | Effects that follow their track's settings while the song plays (`Effect::update`, `Processor::apply`, [Following settings while the song plays](instruments.md#following-settings-while-the-song-plays)) |
| 1.6 | OxiGuitar 0.17 (frozen) | The rest of Guitar Pro 8's notation in the score version 2: fermatas, simile signs, slurs, hairpins, ottavas, slash notation, beaming, barres, fade-outs and swells, pedal, wah, arpeggios, rasgueado, golpe, pick scrapes, dead slaps, wide vibrato, ornaments, string numbers, spellings and bars per system, each a new variant of an extension list (`MasterBarExt`, `BarExt`, `BeatExt`, `NoteExt`, `ScoreExt`, `TrackExt`) |
| 1.7 | OxiGuitar 0.18 | Signatures that recognise XML formats by their first element (`xml_root`), in the file or in a ZIP container's root file (`container_root`), such as MusicXML and compressed MusicXML ([Formats](formats.md#signatures)) |

**Interface 1 is frozen from OxiGuitar 0.2 on.** What exists stays as it is:

- **A newer OxiGuitar loads older plugins.** A plugin built for 1.0 or 1.1 loads in every OxiGuitar with interface 1.x; the host sends it only what its minor version knows (a 1.0 plugin is never asked for a tab).
- **Minor versions only add**: new messages, new variants at the end of an enum, new fields at the end of a C table, new manifest keys. Nothing that exists changes meaning or encoding; tests in the interface crate pin every encoding.
- **An older OxiGuitar refuses newer plugins** that ask for a minor version it doesn't have, and says so in Tools → Plugins. Ask for the lowest version that has what you use: `1.0` for a format or service plugin, `1.1` for tabs or events, `1.2` for tools, changes to the score, the editor's selection or the score version 2, `1.3` for a settings window, track sections, footer links or folders, `1.4` for links in a tab, exporters, `needs`, `replaces` or advice, `1.5` for effects that follow their settings while the song plays, `1.6` for a format that reads or writes the notation above, `1.7` for a format recognised by its first element (`xml_root`, `container_root`). The template builds against the SDK of OxiGuitar 0.11 (the tag `v0.11.0`, interface 1.4, crates 1.4.0), which reaches the most users; take `v0.14.0` (interface 1.5, crates 1.5.0) for an effect that follows its settings while the song plays, `v0.17.0` (interface 1.6, crates 1.6.0) for a format that reads or writes the notation of 1.6, and `v0.18.0` (interface 1.7, crates 1.7.0) for a format recognised by its first element. A plugin file also says which SDK made it, and an OxiGuitar older than that SDK refuses it whatever its manifest asks for: a plugin built with `v0.14.0` loads in OxiGuitar 0.14 and later.
- **A new major version** (`2.0`) would have its own entry point, `oxiguitar_plugin_v2`; OxiGuitar would refuse plugins built for another major version, naming the version they need.

The score crosses the interface as its own types, which don't follow the core's model as it grows. Version 1 (`oxiguitar_plugin::score`) is frozen. Version 2 (`oxiguitar_plugin::score2`, interface 1.2) has the same tree, and each of its parts ends in a list of extensions (`ext`), an enum that later minor versions extend at its end: free time is the first (`MasterBarExt::FreeTime`). OxiGuitar leaves out the extensions a plugin's version doesn't know before sending it a score, and a plugin built for 1.0 or 1.1 gets version 1, with what version 1 can't hold named as losses when it writes a file. So there is never a version 3: what M5's notation adds arrives as extensions.

**Interface 1.7 comes with OxiGuitar 0.18** (the tag `v0.18.0`) and is frozen with it, as 1.6 was with 0.17 (`v0.17.0`), 1.5 with 0.14 (`v0.14.0`) and 1.4 with 0.11 (`v0.11.0`). The plugin repositories depend on one of these tags; the SDK crates change only with the next minor version, and their version is the interface's, not the program's.

What comes next, each when a plugin needs it: toolbar sections, and instruments that follow their settings while the song plays. Each will be a minor version. If your plugin needs something the interface doesn't have, [open an issue](https://github.com/mateusrdp/oxiguitar/issues/new) saying what.
