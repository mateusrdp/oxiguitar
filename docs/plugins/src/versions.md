# Interface versions

The plugin interface has a major and a minor version, `MAJOR.MINOR`. A plugin's manifest says which it was built for (`"interface": "2.0"`), and the SDK it was built with knows that version.

| 2.0 | The next OxiGuitar (not released yet) | **Interface 2.0** is 1.16 without the plugin UI OxiGuitar drew itself: tabs and dialogs made of widget rows, the canvas, surfaces, links among widgets and track sections' widgets are gone, and so are the settings windows and named shared folders 1.9 and 1.10 had retired. Everything else of interface 1 is in 2.0 |

**Interface 2 is the current major version.** A plugin built for interface 1 doesn't load in an OxiGuitar with interface 2 (Tools → Plugins says it needs updating), and the other way round: rebuild it with the SDK of interface 2, and ask for `"interface": "2.0"`. The entry point is `oxiguitar_plugin_v2`. What the table above says of 1.x is what 2.0 holds, by the minor version that brought it.

- **Minor versions only add**: new messages, new variants at the end of an enum, new fields at the end of a C table, new manifest keys. Nothing that exists changes meaning or encoding; tests in the interface crate pin every encoding.
- **A newer OxiGuitar loads older plugins** of the same major version, and sends them only what their minor version knows.
- **An older OxiGuitar refuses newer plugins** that ask for a minor version it doesn't have, and says so in Tools → Plugins. A plugin file also says which SDK made it, and an OxiGuitar older than that SDK refuses it whatever its manifest asks for.

The score crosses the interface as its own types, which don't follow the core's model as it grows. Version 1 (`oxiguitar_plugin::score`) is frozen. Version 2 (`oxiguitar_plugin::score2`, interface 1.2) has the same tree, and each of its parts ends in a list of extensions (`ext`), an enum that later minor versions extend at its end: free time is the first (`MasterBarExt::FreeTime`). Interface 2.0 knows every extension interface 1 had; OxiGuitar leaves out the ones a later 2.x adds before sending a score to a plugin built for an earlier one. A plugin with a version-1 writer only gets what version 1 holds, and what it can't hold is named as losses. So there is never a version 3: what M5's notation adds arrives as extensions.

Interface 1.16 came with OxiGuitar 0.23.0 (the tag `v0.23.0`, crates 1.16.0), the last of interface 1.

**Interface 2.0 is not frozen yet**: it is on `develop` and comes with the next release (the SDK crates are at 2.0.0); a plugin that needs it depends on a commit of `develop` until the tag exists.

What comes next, each when a plugin needs it: toolbar sections, and instruments that follow their settings while the song plays. Each will be a minor version. If your plugin needs something the interface doesn't have, [open an issue](https://github.com/mateusrdp/oxiguitar/issues/new) saying what.
