# Interface design rules

These rules come from Mateus's review of the GUI spike (16 October 2026) and his plan for a plugin-first window (18 October 2026). They apply to `oxiguitar-app`, and to any plugin that adds tabs, toolbar sections or palette entries. The app (`crates/oxiguitar-app`, binary `oxiguitar`) follows them; the Slint spike in `spikes/gui/slint` was the reference for the palette, which shows greyed out from M2 and works with the editor in M3.

## The window

Five areas, a toolbar above them and a footer below (Mateus, 18 Oct 2026; docs/design/plugins.md, "The window"). The window's shape lives in `shell.rs` and the footer's messages in `footer.rs`, without window code, and both are unit-tested. The core's tabs and toolbar sections are entries in the same lists plugins will add to, so the window assumes no fixed set.

- **Menus:** File (Open… Ctrl + O, Export PDF…, Paper Size: A4 or Letter, Quit Ctrl + Q), Edit (Undo Ctrl + Z and Redo Ctrl + Y, each naming its change, Select All Ctrl + A; M3), View (Layout, Dark Interface, Dark Page, Dynamics, Toolbar, Panels: Top, Bottom F8, Left F7, Right), Tools (the tools, Next Bar That Doesn't Add Up F4, then Plugins…), Help (Keyboard and Mouse F1, About, which also lists the plugin folders in search order and says when safe mode is on).
- **Plugin manager** (Tools → Plugins…; `manager.rs`, `ui/plugin_manager.slint`): a separate, non-modal window, opened only from that menu entry and shown again (in front) when chosen again; Close hides it. One row per plugin file: a tickbox (only for files that can be enabled or disabled), the name and version, a sentence for its state (loaded, not loaded yet, disabled, not used because another file holds the same plugin, or why it can't be used), and the folder and file name, dimmed. A tick writes `disabled` in settings.json at once. Plugins can't be unloaded while the app runs (ADR 0008), so the row says what a restart changes ("Loaded: it stays in use until OxiGuitar restarts, and is disabled from then on"), one line beside Close says "Restart OxiGuitar to apply these changes" while any change waits, and unticking a loaded plugin also says so in the footer (Mateus, 18 Oct 2026). It follows Dark Interface. Nothing marks a plugin as ours or anyone else's (Mateus, 18 Oct 2026). When settings.json couldn't be read at start, the tickboxes are greyed out and one amber line says why. `oxiguitar --safe-mode` starts with no plugin used; the manager then says so and still lists every file. The Edit menu arrived with the editor (M3 slice 1).
- **Toolbar** under the menus, in sections separated by a thin rule: File (Open, Save, Export PDF) and Edit (Undo, Redo). Only what users click often belongs there; settings made once, such as Dark Page, live in the View menu only (Mateus, 18 Oct 2026). Undo and Redo work from M3 slice 1, greyed out while there is nothing to undo or redo; Save comes with the .gp writer (slice 2). Icons are our own SVGs in `assets/icons/ui/`, white strokes tinted by the theme, 18 px in 30 × 28 buttons; tooltips give the name and shortcut. View → Toolbar hides it. Plugins add sections with their own icons.
- **Four tabbed areas.** Top (the Player tab) and bottom (Tracks) span the window; left (Palette) and right (Inspector) sit beside the page. There is no Mixer tab: the mixer's controls sit in each track's row ("Track list", below; Mateus, 19 Oct 2026). Each has a tab strip: clicking a tab opens it, clicking the open tab's name or the strip's chevron collapses the area to its strip (a side area to a 26 px strip that opens again with a click), and View → Panels hides it altogether. Splitters resize them. Top, bottom and left start open, the left with the editor's palette, greyed out until the editor ("Palette" below; Mateus, 19 Oct 2026); the right starts collapsed while it holds only a placeholder. A tab whose content doesn't exist yet shows one muted sentence saying what it will hold.
- **Plugin tabs** (slice 3; `plugin_tabs.rs`, `ui/plugin_tab.slint`): a plugin's tabs join the area its manifest names, after the core's, titled from the manifest, so nothing is loaded until one is opened. Their contents are rows of the window's own widgets (labels, buttons, tickboxes, sliders, one-line fields, drop-downs, lists), in the window's style and colours, and canvases the plugin draws, as large as the room allows with their proportions, on the panel's own colour and redrawn when Dark Interface changes. A thread of their own asks the plugins and draws the canvases, so the window never waits for a plugin; drags it hasn't answered yet are merged. Rows that keep their shape are changed in place, so a canvas being dragged on is never rebuilt. While the plugin is first asked the tab says so, and contents it can't show become one muted sentence saying why (also in the footer, once).
- **Player** (top area): rewind, play, play selection, pause, stop; count-in, loop, metronome; and the Output drop-down that picks the output plugin. All are greyed out while no output plugin is installed, and the footer says where to get one.
- **Canvas:** the score, centred on `#242528` whether or not Dark Page is on (Mateus, 18 Oct 2026), with scroll bars. The **mouse wheel over the page scrolls it**, along the line in the Horizontal layout when it fits the window's height; **Shift + wheel zooms the score** around the pointer, about 9 % a notch (2^(1/8)) (Mateus, 18 Oct 2026, swapping the two; a Shift + wheel that the system turns into a sideways scroll, as macOS does, zooms too). Elsewhere in the window the wheel scrolls lists as usual. Page Up / Page Down and Space scroll too; the arrow keys, Home and End move the editor's caret once a score is open (scrolling only before). Before a file is open, one muted line says how to open one. The wheel is handled in the window's raw events (`install_window_events`), where the pointer's position decides whether it is over the page, so no widget scrolls the page by accident.
- **The caret and the selection** (M3 slice 1; `editing.rs`, without window code): a translucent box over the caret's beat across its staves, with its string framed on the tablature, and translucent boxes over what is selected, all in the score's accent green (`Look.accent`). They are drawn over the tiles, in canvas points scaled by the zoom (`pt-scale`), so moving them redraws no tile and they follow zooming and resizing by themselves. The window keeps a shared, read-only copy of the score and the engraver's map of where each beat and string is (`Hits`), so a key or a click moves the caret without waiting for the worker. A press on the page puts the caret on the beat of its voice nearest the pointer and on the string under it; Shift + press selects up to it. Keys as Guitar Pro 8's (its shortcut list, checked 19 Oct 2026): Left and Right by beat across bar lines, Up and Down by string, Home and End within the bar, Ctrl + Home and Ctrl + End to the first and last bars, Tab and Shift + Tab by staff, Ctrl + Up and Ctrl + Down among the shown tracks (with a single track shown, the previous or next track of the song takes its place, as in Guitar Pro's single-track view; Mateus, 19 Oct 2026), Ctrl + 1 to 4 for the voices; Shift extends the selection, Ctrl + Shift + Left and Right by bar; Ctrl + A selects all, Escape drops the selection. Ctrl + Left and Right stay free for the player (Guitar Pro 8's rewind and fast forward). The view scrolls to keep the caret in sight. Every move tells the plugins that listen (selection events).
- **Bars that don't add up** are laid in translucent red (`Paint::Warning`) on screen, never in a PDF. The footer says how many and where the first is, once, when the file opens; Tools → Next Bar That Doesn't Add Up (F4, Guitar Pro 8's "Check bar duration" key) walks the caret through those of the shown tracks.
- **Score zoom slider** bottom right, as below. The slider keeps the middle of the view in place. In the Vertical layout the lines are as wide as the window, so zooming, resizing or opening a side area reflows the bars.
- **Footer**, one line under everything: the latest message with a coloured dot (amber warning, red error) and, when there are several, how many. It holds errors and warnings only, never a log (Mateus, 19 Oct 2026): a reader's import log, the plugins found, a tool's report and a finished export aren't shown there. A click expands it to 160 px with every message of the session, newest first, scrollable; the chevron in its corner folds it back. It replaces M1's status pill. Messages stay until a newer one arrives. At start it says what the plugin folders lack (no output plugin, no read/write plugins), and nothing when everything is there.
- **Track list**, the bottom area's Tracks tab. Each row (Mateus, 19 Oct 2026): the name, the track's mixer (mute, solo, volume, pan; next item), then two **notation buttons**, tablature and standard notation, and last the track across the song ("Track overview", below), filling the rest of the row. No number and no string count: the name says which track it is, and the strings show in the score. The notation buttons: a G clef for standard notation and the vertical TAB sign for tablature (tracks without strings have only the clef). The buttons are drawn by our renderer, centred on their ink and highlighted when on, like the spike's palette buttons (`icons.rs`). Any combination is allowed: standard notation, tablature, both, or neither, which hides the track; a notation button on a hidden track shows it in that notation (Mateus, 16 Oct 2026). There is no separate show tick: the buttons already show and hide tracks, and one control can't fall out of step with another (Mateus, 17 Oct 2026). The last shown track cannot be hidden. Tablature starts on only for fretted instruments (see engraving.md, "Clefs, tablature and keyboards"). Clicking a name selects the track for the editor, highlighting it and moving the caret to it (Mateus, 19 Oct 2026; M3 slice 1); clicking another track's notation button adds it, so several tracks line up in one score without a separate "show all" switch — the buttons already do that job, so there's nothing left for a Multitrack menu item to add, and one less control to keep in sync (Mateus, 17 Oct 2026). Opening a score shows the Tracks tab; the area's height fits up to five tracks and the splitter changes it. The rules live in `tracks.rs`, without window code, and are unit-tested.
- **The track dialog** (Mateus, 19 Oct 2026; with the editor, M3, slice 5): a click on a track's row selects the track, and a right-click opens a menu with Properties (also Edit → Track Properties…), Transpose… (the whole track) and Delete (which asks first). A right-click on a selection in the page offers Transpose… for that selection; Tools → Transpose… transposes every track. Properties opens a modal dialog: the name, instrument and capo and, for stringed instruments, the number of strings and the tuning, as a key field and a pattern drop-down (Standard, Drop, Open with the root on the lowest string as in Open D, Open with the fifth on the lowest string as in Open G, Other; "X Standard" covers E Standard, E♭ Standard, D Standard and the rest). Other keeps the key and lets each string take any note, checked only as a note and against the number of strings. Tunings are named that compactly wherever they show. A track is shown when its TAB or standard-notation button is on; no other control shows or hides it (slice 1 turns the name's click from "show alone" into "select").
- **The mixer is in the Tracks tab** (Mateus, 19 Oct 2026): no tab of its own. Each track's row carries its mixer controls between the name and the notation buttons, all compact, in this order: icon toggles for mute (a loudspeaker crossed out) and solo (headphones), drawn by our renderer and highlighted like the notation buttons (`icons.rs`, `toggles`), a slider for volume (96 px) and a knob for pan. A track without strings keeps an empty slot where its TAB button would be, so the clefs line up in one column. The pan knob turns through 270°, its mark pointing left at full left, up at the centre, right at full right; dragging up or to the right turns it right, the arrow keys move it a tenth, and a double click centres it. The controls start at the values the file sets (`Mixer` in `tracks.rs`), and nothing is ever written back to the file. The playback speed sits with the player's controls in the top area. Like those controls, the mixer's are greyed out until an output plugin is installed, with tooltips that say they come with the player; with one installed they move and toggle, and they reach the sound from M4 (PLAY-6).
- **Track overview** (Mateus, 19 Oct 2026): the end of each row shows the track across the whole song, like a waveform: how much it plays in each bar (the notes it strikes there, every staff and voice, relative to the busiest bar of any track, as a square root so quiet bars still show; `activity` in `document.rs`), mirrored around a line that is all that shows where it is silent (`waveform` in `tracks.rs`: SVG path data drawn by a Slint `Path` stretched to the row, so it follows the area's width). A shown track's is brighter. The playback position is a line with a playhead on top across it; until the player (M4) it is a placeholder, greyed out at the start of the song, whose tooltip says it comes with the player, so the row shows where it will be and what it will look like. With the player it follows playback, and a click on the overview will be a natural place to move it.
- **Ticks in menus** are two-way bound in Slint and set from one place (`pick-layout`, `pick-paper`): a checkable item flips its own tick when clicked, which breaks a one-way binding such as `checked: layout == 0`, so the layout and paper items behave like radio buttons only this way.
- **Window title** is just "OxiGuitar" (no file name), as Mateus asked.
- **Icon:** the placeholder pick (`assets/icon/`, PNGs in `assets/icon/png/`) is the window icon on X11, Windows and macOS. Wayland compositors ignore window icons: they show the icon of the desktop entry named by the window's app id, `io.github.mateusrdp.OxiGuitar` (`assets/linux/`). The packages will install the entry and icons; for a build from source, `scripts/install-desktop-entry.sh` installs them for the current user.
- **Open and Export dialogs** are the system's own, through the XDG desktop portal on Linux; they run on their own thread so the window keeps drawing (on macOS on the main thread, as the system requires). If the session has no D-Bus for the portal, the footer says so and suggests `oxiguitar FILE`. A file named on the command line opens at start, which is also how file managers open files (UI-4). A file dropped on the window opens too; of several files, the first opens. This works on Windows, macOS and X11 (winit's `DroppedFile`), **not on Wayland**: winit 0.30 and Slint 1.18 report no drops there, and a workaround of our own (`unsafe` plus polling) was rejected. ADR 0006 says what has to change upstream. On macOS a double-click in Finder starts OxiGuitar but doesn't open the file: macOS sends it as an Apple Event that winit and Slint don't pass on, and catching it ourselves would need `unsafe` Objective-C glue (ADR 0007).
- **PDF export** writes the tracks shown, in the Page layout, on the paper chosen under File → Paper Size, always on a light page (EXP-1), next to the score by default.
- **Drawing:** a worker thread reads, engraves and draws 512-pixel tiles at the screen's pixel density; the window shows them as they arrive, nearest the middle of the view first, and keeps those near the view. Scrolling never waits for engraving. After a zoom, a new engraving or Dark Page, the old tiles (scaled to the new zoom) stay underneath until the new ones cover the view, so the canvas never goes blank.

## Principles

1. **Minimal.** Screen space belongs to the score. Every visible control must earn its place; when in doubt, leave it out, put it in a menu, or make it a shortcut.
2. **No labels that state the obvious.** No app name inside the window (the title bar says "OxiGuitar"), no caption repeating what a highlight already shows, no "Tracks" heading over the track list.
3. **Menus and one toolbar on top.** File, Edit, View, Help (and later Track, Note, Tools, Playback, as Guitar Pro has), then a single toolbar of sections (Mateus, 18 Oct 2026, replacing the M1 rule of menus only). Everything else lives in the four areas, which the user can collapse or hide. Display options live under View or in Preferences.
4. **The user decides what is shown.** Every area collapses and hides from View → Panels, the toolbar from View → Toolbar, and two have keys (F7 left, F8 bottom). Palette tools come in groups that collapse and expand with a click on their heading.
5. **Look like Guitar Pro 8, without copying it** (UI-1, UI-3): same places for things, same shortcuts, our own drawing.

## Zoom

There are two zooms, and they never share a control.

| Zoom | What it scales | How | Visible control |
| --- | --- | --- | --- |
| Interface | Everything in the window: menus, palette, panels, text | Ctrl + mouse wheel anywhere; Ctrl + `+` (or `=`) in, Ctrl + `-` (or `_`) out, Ctrl + `0` back to 100 %; numeric keypad too | None. Documented in Help → Keyboard and Mouse and in the manual. |
| Score | The score canvas only, 25 % to 400 % | Shift + mouse wheel over the page, around the pointer (Mateus, 18 Oct 2026); a slider in the bottom-right corner of the canvas | The slider: logarithmic, so 100 % sits in the middle; it snaps to 100 % near the middle; clicking its percentage returns to 100 %. About 170 px wide in all. |

Interface zoom follows browser steps (50, 67, 75, 80, 90, 100, 110, 125, 150, 175, 200 %) and multiplies the system's scale factor, so it stays right when the window moves to another monitor. It is caught before any widget sees it, so Ctrl + wheel over the score never scrolls it.

## View options

Everything about how the score is shown lives in the View menu:

- **Layout** (VIEW-3, M1): how staves are laid out, as in Guitar Pro.
  - **Page**: systems fill the page width, stack vertically and break into pages.
  - **Vertical**: systems fill the window width and stack vertically, with no pages.
  - **Horizontal**: one single long line, scrolling sideways.
  - **Parchment**: one single long vertical column, with no page breaks.

  These follow Mateus's description (16 October 2026), checked against the Guitar Pro 8 user guide before they were built: they are GP8's Page – Vertical, Screen – Vertical, Screen – Horizontal and Page – Scroll ([engraving.md](engraving.md#layouts-view-3)).
- **Dark Interface**: the window's own colours, dark by default (Mateus, 18 Oct 2026), switched through Slint's `Palette.color-scheme`.
- **Dark Page** (VIEW-8): light notation on a dark page. Page colours are themes of the display list (`Theme::LIGHT`, `Theme::DARK` in `oxiguitar-display`), so the PDF can use them too. Off by default: the page is white.
- The View menu's choices (interface, page, dynamics, layout, paper) are kept in settings.json under `view` (`prefs.rs`) and restored at start.
- The toolbar, and the four panels under View → Panels.
- **Dynamics**: shows or hides dynamics markings (on by default), for scores where they clutter the page.

## Tools menu

The Tools menu lists the tools of `oxiguitar-tools` in order ([tools.md](tools.md)). An entry that cannot run on the open score is greyed out. Slint's menus have no tooltips, so the reason follows the name in brackets, such as "Infer Key Signatures (the score already has key signatures)"; descriptions go in the manual. Picking one applies it and shows its report in the footer. The file on disk is never changed: reopening it shows what it says. In M3 (the editor) applying a tool becomes one undoable command. Plugins add their tools to the same menu from M2.

The first tool is **Infer Key Signatures** (16 Oct 2026).

## Palette

The editor's palette fills the left area from M2, every tool greyed out until the editor (M3), so people trying OxiGuitar see where it is going (Mateus, 19 Oct 2026). It is built in `palette.rs` (the tools and their drawings, no window code) and `icons.rs` (the drawing), and shown by `PaletteView` in `app.slint`.

- **Guitar Pro 8's groups and tools**, in its order, with its names, checked against its user guide ("Editing Palette Symbols", 19 Oct 2026): **Voices and modes** (Edit Voice 1–4, Multivoice, Design Mode, Lyrics, Chords: the buttons at the top of GP8's palette), **Bar** (16: clef, key and time signatures, rhythmic interpretation, free time, double bar line, repeat signs, repeat start and close, alternate endings, directions, octaviations), **Note** (34: note values to the 64th, rest, dots, triplet and any n-tuplet, nested tuplets, ties, fermata, accidentals, semitone up and down, dynamics from ppp to fff, crescendo and decrescendo), **Effects** (56, from ghost note to dead slap), **Notation** (10: chord, slash, extended barre, text, section, beaming, tuplet groups). 124 tools. Guitar Pro 8's Automation group (tempo, volume and pan automations), its Timer and both its stem-direction tools (automatic and inverted) are left out (Mateus, 19 Oct 2026): stems go by voice only, odd voices up and even voices down.
- **Greyed out until the editor.** Every button is disabled; its tooltip gives the tool's name and says it comes with the editor ("Bend (comes with the editor)"). The tools work from M3, each enabled as its slice arrives, its tooltip then giving its shortcut. Slice 1: Edit Voice 1 to 4 (Ctrl + 1 to 4), highlighted on the caret's voice (Mateus, 19 Oct 2026: the palette should show which voice the caret is in).
- **Groups collapse and expand** with a click on their heading (a chevron and the group's name), for the session. All start expanded; the area scrolls.
- Buttons are 32 × 32 logical pixels, wrapping to the area's width (six across at the default 220 px).
- **Icons are drawn by our renderer, not typed as text** (UI-10). A face is a Bravura symbol, a short label in the interface font (H, P.M., rasg.), or a small drawing made of symbols, lines and curves placed in staff spaces, the way the engraver draws the page (a notehead with its accent, a slide between two notes, a chord diagram, a stopwatch). Each face is drawn once to measure its ink, then drawn again scaled so the centre of its ink's bounding box is the centre of the button, with a margin all round. Note values (with the rest and the dotted notes) share one scale so their sizes compare, and so do the dynamics; text labels share one size; every other face is fitted on its own, but never larger than twice the note values' scale, so a lone notehead stays small. Icons are white on transparent, tinted by the toolkit, and redrawn for the screen's pixel density and the interface zoom. The palette's faces are measured on a thread of their own at start, so the window never waits for them. Tests check that every icon is inside its button and centred within a pixel at 100 %, 125 %, 150 % and 200 %, and that every Bravura symbol used has the ink Bravura's metadata gives for its name (a wrong codepoint can't pass for the right symbol). `OXIGUITAR_ICON_SHEET=icons.png cargo test -p oxiguitar-app icon_sheet` draws them all into one picture to look at.
- Selection will be shown by the button's highlight only.
- **With the editor (M3):** the tools work, each with a shortcut following Guitar Pro 8's, checked against its user guide's shortcut list when they are bound, and shown in its tooltip; a compact search field at the top of the palette filters tools by name, keeping groups' collapsed state while searching (its shortcut to be chosen then: Guitar Pro 8 uses Ctrl + K for the key signature).
- **Tuplets** (EDIT-10, M3): the Triplet tool, with a shortcut, makes triplets; Custom N-tuplet opens a small dialog to choose any grouping, n notes in the time of m, with the usual m filled in (Mateus, 16 Oct 2026).

## Accessibility

Keyboard use is required: every tool has a shortcut (UI-2) and Tab moves through controls. Screen-reader support is a late nice-to-have, not a goal for v1.0 (decided 16 October 2026); Slint's AccessKit support keeps the door open.
